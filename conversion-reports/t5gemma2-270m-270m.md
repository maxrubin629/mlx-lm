# T5Gemma2 270M-270M MLX Conversion Report

Model: `google/t5gemma-2-270m-270m`

Scope: text-only sequence-to-sequence conversion for `mlx-lm`. The encoder uses
the Gemma 3 text stack only; SigLIP image tower and multimodal projector weights
are intentionally ignored by `sanitize`.

## Implementation

- Added `mlx_lm.models.t5gemma2` with encoder, decoder, cross-attention, tied
  output projection, text-only embedding handling, and cache creation for
  encoder-decoder generation.
- Added encoder-decoder greedy generation support in `mlx_lm.generate`.
- Added nested dtype resolution in `mlx_lm.convert`, so configs with dtype under
  top-level, text, encoder, or decoder sections resolve consistently.
- Added targeted model tests for forward/cache behavior, sanitization, generation,
  and dtype resolution.

## Speed Pass

Applied MLX performance changes:

- Use `mx.fast.scaled_dot_product_attention` for T5Gemma2 attention when
  `attn_logit_softcapping` is disabled, retaining the manual path only for
  softcapped attention.
- Skip building an all-true self+cross mask for cached single-token decoder
  steps when there is no encoder attention mask.
- Let `mx.fast.rms_norm` handle accumulation precision directly instead of
  explicitly upcasting and downcasting every norm call.

Benchmark command:

```bash
.venv/bin/python - <<'PY'
import time, statistics
import mlx.core as mx
from mlx_lm import load
from mlx_lm.generate import generate_step

model_path = "downloads/google-t5gemma-2-270m-270m-mlx"
prompt = "Translate English to French: The weather is nice today."
max_tokens = 96
runs = 5
model, tokenizer = load(model_path)
tokens = mx.array(tokenizer.encode(prompt))
sampler = lambda logprobs: mx.argmax(logprobs, axis=-1)

for _ in generate_step(tokens, model, max_tokens=16, sampler=sampler):
    pass
mx.eval(model.parameters())

times = []
for _ in range(runs):
    t0 = time.perf_counter()
    n = 0
    for _tok, _logprobs in generate_step(
        tokens, model, max_tokens=max_tokens, sampler=sampler
    ):
        n += 1
    times.append(time.perf_counter() - t0)
print(max_tokens / statistics.median(times))
PY
```

### 1B 8-Bit Discrepancy Investigation

The discrepancy is caused by quantizing the 1B encoder projection layers. It is
not from the tied text embedding/output projection: `ScaledEmbedding` is skipped
by the T5Gemma2 quantization predicate.

Diagnostic prompt:

```text
Translate English to French: The weather is nice today.
```

First decoder-step comparison, 1B:

```text
unquantized:
  top-1 token: "," (id 236764), logit 22.25
  top-1 margin over ":" was 0.25

all linear 8-bit:
  quantized modules: 364
  top-1 token: "\n\n" (id 108), logit 25.625
  top-5 overlap with unquantized: 2/5
  top-10 overlap with unquantized: 6/10
  logit diff: max 10.8047, mean 1.8211

encoder-only 8-bit:
  quantized modules: 182
  top-1 token: " English" (id 5422), logit 25.5
  top-5 overlap with unquantized: 2/5
  top-10 overlap with unquantized: 5/10
  logit diff: max 10.8594, mean 1.8286

decoder-only 8-bit:
  quantized modules: 182
  top-1 token: "," (id 236764), logit 22.5
  top-5 overlap with unquantized: 4/5
  top-10 overlap with unquantized: 8/10
  logit diff: max 1.2812, mean 0.2813
```

Splitting encoder quantization further shows that both encoder attention and
encoder MLP projections are sensitive in the 1B model:

```text
encoder attention only:
  quantized modules: 104
  top-1 token: " weather" (id 7606)
  top-5 overlap: 2/5
  logit diff: max 13.3750, mean 1.9861

encoder MLP only:
  quantized modules: 78
  top-1 token: "\n" (id 107)
  top-5 overlap: 0/5
  logit diff: max 19.6875, mean 5.1074
```

Fine-grained 1B encoder projection checks:

```text
encoder q_proj only:
  top-1 token: "\n\n"
  top-5 overlap: 2/5
  logit diff: max 11.0078, mean 1.8655

encoder k_proj only:
  top-1 token: " weather"
  top-5 overlap: 2/5
  logit diff: max 12.8438, mean 1.9960

encoder o_proj only:
  top-1 token: "\n\n"
  top-5 overlap: 2/5
  logit diff: max 10.5625, mean 1.8427

encoder up_proj only:
  top-1 token: " English"
  top-5 overlap: 2/5
  logit diff: max 13.6719, mean 3.1819
```

The 270M control does not show the same ranking failure. Its unquantized first
token has a much larger margin:

```text
270M unquantized:
  top-1 token: "<unused6237>" (id 262139), logit 30.625
  next token logit: 16.625

270M all linear 8-bit:
  top-1 token unchanged
  top-5 overlap: 4/5
  top-10 overlap: 10/10
  logit diff: max 3.5, mean 0.8226

270M encoder-only 8-bit:
  top-1 token unchanged
  top-5 overlap: 4/5
  top-10 overlap: 10/10
  logit diff: max 1.2812, mean 0.2042
```

Conclusion: the 1B discrepancy is an encoder quantization sensitivity issue.
Several encoder projection families introduce enough 8-bit affine quantization
noise to move first-step logits by multiple points. Because the unquantized 1B
first-token decision is already low-margin, those encoder-side shifts flip
greedy decoding immediately. Decoder-side 8-bit quantization is comparatively
small on the same prompt and preserves the first token.

Per user request, the 270M and 1B source downloads used for this investigation
were kept locally after the diagnostic run.

### Quantization Policy Fix

The default T5Gemma2 quantization policy now leaves the encoder unquantized and
quantizes decoder linear layers only. This preserves the stable decoder-side
compression path while avoiding the encoder projection noise identified above.
Custom quantization predicates can still override this default for experiments.
